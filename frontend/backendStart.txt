# Backend Local Development Guide
# Instructions for running the .NET backend locally (without Docker)

## 🚀 STARTING THE BACKEND

### Step 1: Start Database (Docker)
# First, make sure Docker Desktop is running, then start only the database:
cd docker/compose/dev
docker compose up database -d

# Verify database is running:
docker compose ps
# You should see: choruko_dev_db running on port 5432

### Step 2: Navigate to Backend Directory
cd ../../../backend/ChorukoAPI

### Step 3: Restore Dependencies (first time or after changes)
dotnet restore

### Step 4: Apply Database Migrations (first time or after DB changes)
dotnet ef database update

### Step 5: Start the Backend
dotnet run

# Alternative: Start with specific environment
dotnet run --environment Development

# Alternative: Start in watch mode (auto-restart on file changes)
dotnet watch run

## 🔍 CHECKING IF BACKEND IS RUNNING

### Method 1: Check Terminal Output
# When backend starts successfully, you should see:
# info: Microsoft.Hosting.Lifetime[14]
#       Now listening on: https://localhost:7049
# info: Microsoft.Hosting.Lifetime[14] 
#       Now listening on: http://localhost:5049

### Method 2: Test API Endpoints
# Open browser or use curl:
# HTTP:  http://localhost:5049/api/auth
# HTTPS: https://localhost:7049/api/auth

# PowerShell test:
Invoke-WebRequest -Uri "http://localhost:5049/api/auth" -Method GET

# curl test:
curl http://localhost:5049/api/auth

### Method 3: Check Process
# PowerShell:
Get-Process -Name "ChorukoAPI" -ErrorAction SilentlyContinue

# Find process using port:
netstat -ano | findstr :5049

## ⏹️ STOPPING THE BACKEND

### Method 1: Terminal
# In the terminal where backend is running:
# Press Ctrl+C

### Method 2: Kill Process (if stuck)
# PowerShell - find and kill process:
$process = Get-Process -Name "ChorukoAPI" -ErrorAction SilentlyContinue
if ($process) { $process | Stop-Process -Force }

# Or by port:
$netstat = netstat -ano | findstr :5049
# Extract PID from output and kill it:
# taskkill /PID [PID_NUMBER] /F

## 🔧 CONFIGURATION & TROUBLESHOOTING

### Database Connection
# Backend connects to Docker database with these settings:
# Host: localhost
# Port: 5432
# Database: choruko_dev
# Username: developer
# Password: developer

### Common Issues & Solutions

#### Issue: "Database connection failed"
# Solution: Make sure Docker database is running
cd docker/compose/dev
docker compose ps
docker compose up database -d

#### Issue: "Port already in use"
# Solution: Check what's using the port
netstat -ano | findstr :5049
# Kill the process or use different port

#### Issue: "Entity Framework errors"
# Solution: Update database schema
dotnet ef database update
# Or create new migration:
dotnet ef migrations add [MigrationName]

#### Issue: "Package restore errors"
# Solution: Clean and restore
dotnet clean
dotnet restore

#### Issue: Backend exits immediately
# Solution: Check for compilation errors
dotnet build
# Check logs for detailed errors

### Development Workflow Commands

# Clean build:
dotnet clean && dotnet build

# Run tests:
dotnet test

# Check EF migrations status:
dotnet ef migrations list

# Add new migration:
dotnet ef migrations add [MigrationName]

# Reset database (WARNING: deletes all data):
dotnet ef database drop
dotnet ef database update

## 🌐 BACKEND ENDPOINTS

Once running, backend is available at:
- HTTP: http://localhost:5049
- HTTPS: https://localhost:7049

### API Endpoints:
- GET  /api/auth/userinfo - Get current user info
- POST /api/auth/register - Register new user
- POST /api/auth/login - Login user
- POST /api/auth/logout - Logout user

### Swagger Documentation:
# Available at: https://localhost:7049/swagger (in Development mode)

## 📝 QUICK REFERENCE

# Start everything (run these commands in order):
cd docker/compose/dev && docker compose up database -d
cd ../../../backend/ChorukoAPI && dotnet run

# Stop everything:
# Ctrl+C (in backend terminal)
# docker compose -f docker/compose/dev/docker-compose.yml stop database

# Restart backend only:
# Ctrl+C, then: dotnet run

# Check status:
curl http://localhost:5049/api/auth || echo "Backend not running"

## 🔄 INTEGRATION WITH FRONTEND

When running frontend locally, update authService.ts:
const API_BASE_URL = 'http://localhost:5049/api/Auth';

Or keep using relative paths if frontend runs through proxy.
